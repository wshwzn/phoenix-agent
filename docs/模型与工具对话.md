# 模型与工具对话

## 当前范围

`POST /api/chat` 接收单条用户文本，返回最终回答和本次工具调用明细。普通问候可直接回答；检查 MCP 服务时，由模型返回工具调用请求，后端执行并以 `role=tool` 消息反馈。没有基于关键词的业务路由，也未使用硬编码回答。

当前不包含流式输出、历史聊天、任务持久化、RAG、审批、图流程或实际采集工具。`ping` 只证明 MCP 服务可调用，不证明被排障应用健康。

## 模型配置

配置前缀为 `phoenix.model`，本地环境变量如下：

| 变量 | 默认值与约束 |
| --- | --- |
| `PHOENIX_MODEL_ENABLED` | `false`；设为 `true` 才创建模型客户端 |
| `PHOENIX_MODEL_BASE_URL` | 无默认值；HTTP(S) API 根地址，无凭据、查询参数和片段，不含末尾 `chat/completions` |
| `PHOENIX_MODEL_NAME` | 无默认值；必须选支持工具调用的模型 |
| `PHOENIX_MODEL_API_KEY` | 无默认值；只从本地配置读取 |
| `PHOENIX_MODEL_REQUEST_TIMEOUT` | `30s`；大于 0，最多 120 秒，约束单次模型 HTTP 请求 |
| `PHOENIX_MODEL_MAX_OUTPUT_TOKENS` | `2048`；允许 128 至 8192，实际支持上限由厂商决定 |

启用时三项连接字段不能为空；未启用时允许不填。也可复制 `phoenix-server/config/application-local.example.yml` 为同目录已忽略的 `application-local.yml`，填好后激活 `local` profile，并将进程工作目录设置为 `phoenix-server`。该配置在 classpath 外，不会被 Maven 打入 JAR；不要将真实 Key 放到 `src/main/resources`。当前不自动加载 `.env`。

SDK 追加 `chat/completions`，因此 `http://localhost:端口/v1` 会请求 `/v1/chat/completions`。保留厂商要求的路径前缀，不要填写完整补全接口地址。不是所有宣称 OpenAI 兼容的模型都支持同样的工具行为，需用实际厂商验收。

默认关闭原始模型请求/响应日志，禁用 SDK 自动重试，避免重复消耗额度。配置对象的 `toString` 也不输出密钥、地址或模型名称。当前不做配置数据库或供应商管理。

## 接口与明细

请求示例：

```json
{"message":"检查 Phoenix MCP 服务连通性和版本"}
```

`message` 为 1 到 4000 字符的非空文本；客户端不能指定系统提示、历史消息、模型地址、密钥或工具白名单。

| 响应字段 | 含义 |
| --- | --- |
| `requestId` | 本次请求关联标识，可用于匹配日志 |
| `answer` | 模型最终文本，不返回隐藏推理内容 |
| `toolCalls` | 按本次处理顺序返回的工具记录，没有执行时为空 |
| `toolCalls[].callId` | 与模型工具请求及下一轮 tool 消息对应的 ID |
| `toolCalls[].toolName` / `arguments` | 工具名与 JSON 参数文本 |
| `toolCalls[].result` | 成功时为工具实际 JSON 文本，失败或拦截时为安全提示 |
| `toolCalls[].status` | `SUCCESS`、`FAILED`、`BLOCKED`；拦截不等于实际执行 |
| `toolCalls[].durationMs` | 工具执行耗时；本地拦截为 0 |

模型出错、预算耗尽时返回 Problem Detail，包含安全 `code`、`requestId` 和已有 `toolCalls`。这些明细只在响应与请求内存中，不落库；普通日志只记录 ID、错误代码和数量，不打印对话或工具原文。

## 工具循环与授权

1. 检查模型是否配置，再打开 MCP 短会话并发现工具。
2. 只把已发现的 `ping` 提供给模型。当前每次请求都执行发现，所以普通问候也需要 MCP 服务可用；发现不计作工具执行。
3. 模型直接回答则结束；请求工具时先校验整批请求。
4. 限制工具名称、唯一非空调用 ID 和空对象参数，不能通过模型输出自动获得远程新工具权限。
5. 顺序执行本批工具，校验实际返回的服务身份、版本和 PONG，再保存对应 `ToolExecutionResultMessage`。
6. 下一轮发送本次完整消息链，包括同轮和前轮全部工具响应。请求结束关闭会话，不跨请求保留聊天消息。

配置 `PHOENIX_CHAT_MAX_TOOL_ROUNDS` 默认 3（允许 1 至 8）；`PHOENIX_CHAT_MAX_TOOL_CALLS` 默认 3（允许 1 至 10）。轮数是模型提出工具请求的轮数，次数是实际工具调用总数；同轮多个调用也计入次数。一整批超过剩余预算时不会先执行其中一部分。

最多允许“工具轮数 + 1”次模型调用，为执行工具后的最终回答留出一次机会。模型和 MCP 超时分别约束各阶段，不是整个 HTTP 接口的总截止时间。当前为同步非流式接口，断开浏览器不等于取消后端执行。

## 错误代码

| HTTP / 代码 | 含义 |
| --- | --- |
| 400 / `INVALID_MESSAGE` | 缺失、空白、超长消息或无法解析的 JSON |
| 503 / `MODEL_NOT_CONFIGURED` | 模型未启用，应用其他接口仍可使用 |
| 502 / `MCP_UNAVAILABLE`、`MCP_DISCOVERY_FAILED`、`PING_TOOL_UNAVAILABLE` | 工具连接或发现失败 |
| 502 / `MODEL_CALL_FAILED`、`INVALID_MODEL_RESPONSE`、`EMPTY_MODEL_RESPONSE` | 模型请求或最终内容无效 |
| 502 / `INVALID_TOOL_REQUEST` | 模型请求未授权工具、非法参数或缺失/重复调用 ID |
| 502 / `MCP_TOOL_FAILED` | 工具调用失败、结果过大或不符合 ping 结果约定 |
| 422 / `TOOL_BUDGET_EXCEEDED` | 已达到工具轮数或总次数预算 |
| 502 / `CHAT_EXECUTION_FAILED` | 其他对话或资源关闭异常 |

当前两端无身份鉴权，只能用于本机联调，不得直接公开真实模型额度。后续业务工具必须独立鉴权和审批，不能仅靠提示词或工具描述限制操作。

## 测试边界

集成测试使用生产 `OpenAiChatModel` 连接本机模拟兼容协议服务，再通过真实 HTTP MCP 服务执行工具。验证包括真实路径拼接、模型发出工具请求、关联 ID 与 tool 结果回传、同轮和多轮消息、错误脱敏、预算与请求隔离。

模拟模型的行为是测试脚本，不是模型推理能力的评测；普通测试不调用真实厂商、不使用真实 Key，也不能替代用户对实际模型的验收。

实现参考：[LangChain4j 低层工具 API](https://docs.langchain4j.dev/tutorials/tools/)、[OpenAI 兼容模型接入](https://docs.langchain4j.dev/integrations/language-models/open-ai/)。
