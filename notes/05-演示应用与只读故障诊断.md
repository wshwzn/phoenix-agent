# 演示应用与只读故障诊断

## 本轮功能

- demo 增加依赖 Redis 的固定商品查询，Redis 正常时返回商品，依赖不可用时返回安全的 503 与 `REDIS_UNAVAILABLE`。
- 保留与 Redis 独立的探活和健康检查，演示“进程活着但业务失败”。商品读取只执行 GET，不要求初始化数据，不创建业务数据。
- 固定登记 `demo-local`，应用地址、Redis 地址和日志路径由运维配置；模型只能传目标编号。
- MCP 新增 `inspect_application`、`inspect_redis`、`read_recent_logs`，分别采集固定 HTTP 接口、真实 RESP PING 与专用商品诊断事件。
- 工具两端独立校验目标与封闭参数，控制端拒绝重复 JSON 字段；MCP JSON 解析同样启用重复字段检测。未知工具或未发现工具不能执行。
- 成功采集到 DOWN/DEGRADED/MISSING 仍是有效证据，工具明细为 SUCCESS，不把组件故障等同于工具执行失败。
- 默认工具预算调整为 4 轮、6 次；保留同轮/多轮完整消息链，不增加跨请求历史、数据表或持久化任务。
- 限制 HTTP 正文、Redis 响应、日志读取量和输出大小；不透传任意 HTTP 正文、Redis 错误文本或完整业务日志。
- 没有增加 SSH、Shell、Docker Socket、重启或其他写操作。没有接入 LangGraph4j 业务流程、审批、RAG 和记忆。

## 新增类及作用

| 模块 / 类 | 作用 |
| --- | --- |
| demo / `ProductResponse` | 固定演示商品的响应字段 |
| demo / `ProductService` | 定义演示商品查询业务接口 |
| demo / `ProductServiceImpl` | 通过标准 Redis 客户端实际读取商品名称，记录固定安全诊断事件 |
| demo / `RedisUnavailableException` | 表达依赖故障，不包含驱动异常原文 |
| demo / `ProductController` | 提供 `/api/demo/products/1`，把依赖异常映射为安全的 503 |
| MCP / `DiagnosticProperties` | 校验可信应用地址、Redis 地址、日志文件与采集超时；固定授权目标编号 |
| MCP / `DiagnosticService` | 定义应用、Redis 和日志的只读采集接口 |
| MCP / `DiagnosticServiceImpl` | 实际采集和大小/超时控制，生成带来源与时刻的证据 |
| MCP / `DiagnosticTools` | 注册三个 MCP 工具的封闭 Schema，并在采集前验证参数 |
| 控制端 / `ReadOnlyToolPolicy` | 独立校验工具权限、目标、字段、整数类型与返回证据结构 |

## 修改的类与配置

- `ChatServiceImpl`：扩展已发现工具的本地白名单；整批先校验后执行；检查不同工具的证据结构；提示模型区分存活、业务可用、连接失败和历史日志。
- `McpServerConfiguration`：注册四个工具，并通过独立 JSON 解析器拒绝重复字段。
- demo POM：引入 Spring Data Redis，配置 500ms 连接/命令超时。MCP 的固定 PING 不引入通用 Redis 客户端。
- demo `application.yml`：独立的 Redis 演示端口、关闭 Redis 健康贡献者、声明专用诊断日志路径。
- demo `logback-spring.xml`：固定诊断 logger、同步写入、按大小/日期滚动；不采集完整控制台或堆栈日志。
- MCP `application.yml`：维护唯一目标的可信采集地址与路径，默认 500ms 采集超时。
- 控制端 `application.yml`：默认工具预算改为 4 轮、6 次，更新应用说明。
- `.gitignore`：忽略本地配置的编辑器 `~` 备份，保留用户原文件、不读取其内容。
- README、架构、MCP 连通性、模型与工具对话：维护现状；新增 `docs/只读故障诊断.md`，说明 IDEA 工作目录、路径、故障注入与验收方法。
- 无数据库表或字段变更，不操作原智能客服项目、远程服务器或远程仓库。

## 测试类与验证范围

- 新增 `ProductIntegrationTests`：真实业务 HTTP + Redis 客户端替身，验证商品数据、503、探活独立与安全日志。
- 新增 `DiagnosticServiceTests`：真实本机网络与临时文件，验证应用正常/依赖异常/应用停止、重定向拦截、响应大小、Redis PING/认证提示/超时/连接失败、日志白名单与大小、目标和条数约束。
- 新增 `DiagnosticPropertiesTests`：验证 HTTP 根地址、端口、采集超时和文件系统相对路径解析。
- 新增 `DiagnosticMcpIntegrationTests`：生产 MCP 服务实际执行采集，通过本机 HTTP/Redis 协议替身验证正常和停止证据、日志缺失与近期事件。
- 新增 `ReadOnlyToolPolicyTests`：验证额外 URL/路径/命令、重复 JSON 字段、目标编号、整数条数、结果身份/状态和证据结构。
- 修改 `ChatServiceTests`：验证越权目标使整批工具执行前失败，以及尚未发现的诊断工具被拦截。
- 修改 `ChatIntegrationTests` 和 `McpConnectionIntegrationTests`：使用模拟 OpenAI HTTP 与 MCP 协议替身，验证三轮正常/故障证据完整回传；脚本模型不是实际推理能力评测。
- 修改 `PhoenixMcpServerApplicationTests`：验证发现四个工具，以及直接协议调用也无法传入越权参数。
- 修改 `PhoenixDemoApplicationTests`：测试日志固定写入构建目录，确保不同测试上下文使用同一日志目标；探活仍不需要 Redis。

## 验证结果与边界

- `.\mvnw.cmd -B -ntp clean verify` 成功：控制端 108、MCP 51、demo 6，共 165 项测试；失败、错误、跳过均为 0。三个可执行 JAR 均完成打包。
- 手动启动打包后的真实 demo 和 MCP 两个独立进程，使用独立的 28182/28181 端口，并指向确认未监听的 Redis 测试端口 38179：通过真实 MCP 初始化、工具调用和会话关闭，验证探活与健康 HTTP 200、商品 HTTP 503/REDIS_UNAVAILABLE、Redis DOWN/CONNECTION_REFUSED、近期日志读到实际 demo 写入的失败事件。不是 mock 商品服务，也未访问用户 Redis。
- 手动验证完成后关闭两个临时进程；未修改默认端口和用户本地配置，没有留下后台测试服务。
- `git diff --check` 通过；本地配置及其 `~` 备份命中忽略规则，可执行控制端 JAR 不包含 `application-local`。
- 构建测试曾发现配置中的 `Path` 被 Servlet 资源转换器解释，以及多测试上下文首次日志配置路径不一致，均已修正并重新完整清理构建通过。
- 普通测试不访问用户 Redis、实际模型或 Docker，测试服务使用随机端口并自动关闭。

本机 Docker 守护进程未运行，没有启动 Redis 容器，没有执行实际容器停止/恢复验收，也没有调用用户真实模型。运行说明保留正常、停止和恢复三个手动验收步骤，不能将协议替身测试当成真实环境验证。

当前无身份鉴权，仅本机联调；固定目标不是用户权限系统。Redis 采集只支持本地无认证 PING；日志仅包含有限商品事件，缺失不代表没有故障。不同工具不是原子快照，历史错误不代表当前状态，Redis 连接失败不直接证明容器已停止。
