# 模型接入与自主工具调用

## 本轮功能

- 新增非流式 `POST /api/chat`，单条用户文本触发模型回答或自主请求 MCP ping。
- 支持 OpenAI 兼容协议的 URL、模型名、Key 本地配置，不做供应商管理；默认关闭，未配置模型不影响应用启动。
- 只允许 ping，限制工具轮数和总次数，整批校验授权、ID 和参数后才执行。
- 本次请求内完整保留所有轮次的 assistant 工具请求和 tool 响应，再交给模型；不同请求不共享历史。
- 返回工具调用 ID、名称、参数、实际结果、状态与耗时；失败也保留此前工具明细，当前不落库。
- 加入消息校验、模型超时、输出 token 上限、安全错误和禁用自动重试。
- 使用 LangChain4j 低层模型与工具消息 API 实现节点内部循环，不引入第二套全局编排；本轮不实现 LangGraph4j 任务流程。

## 新增类及作用

| 类 | 作用 |
| --- | --- |
| `ModelProperties` | 校验模型连接与超时配置，打印配置对象时隐藏敏感信息 |
| `ChatProperties` | 校验单次工具轮数和总调用次数预算 |
| `ChatConfiguration` | 显式启用时创建 OpenAI 兼容模型客户端，不在启动时发送请求 |
| `ChatRequest` | 单条用户文本输入与非空、长度校验 |
| `ChatResponse` | 返回请求 ID、最终回答及工具明细 |
| `ToolCallTrace` | 表达工具请求、实际结果、执行状态和耗时 |
| `ChatExecutionException` | 携带安全错误代码、HTTP 状态和已有工具记录快照 |
| `ChatService` | 定义单轮对话业务接口 |
| `ChatServiceImpl` | 调用模型、检查工具请求、执行 MCP、拼接完整消息链并清理会话 |
| `ChatController` | 提供聊天 HTTP 入口与安全的校验/执行错误响应 |
| `ChatIntegrationTests` | 用本机模拟 OpenAI HTTP 服务和真实 SDK MCP 服务验证完整链路 |
| `ChatDisabledTests` | 验证默认未配置行为和 HTTP 输入边界 |
| `ModelPropertiesTests` | 验证模型配置、密钥打印保护和预算约束 |
| `ChatServiceTests` | 验证工具白名单、独立预算、错误结果、关联 ID 和资源释放 |

## 修改的文件与类

- 控制端 POM：增加 Bean Validation，不增加模型厂商 SDK 或数据库依赖。
- `application.yml`：加入模型默认关闭、本地字段占位与聊天预算配置。
- `phoenix-server/config/application-local.example.yml`：提供无真实密钥的外部 profile 配置模板；真实 `application-local.yml` 被忽略且不打入 JAR。
- `McpConnectionIntegrationTests`：开放原有测试配置供聊天集成测试复用，增加实际工具调用计数；不改变生产 MCP 工具。
- README、架构设计：维护当前能力、配置方式与未完成范围；新增 `docs/模型与工具对话.md`。
- 无数据库表或字段变更，不操作原智能客服项目或服务器。

## 验证结果

- `.\mvnw.cmd -B -ntp clean verify`：三个模块完整清理构建成功，共 78 项测试通过，失败、错误、跳过均为 0。
- 使用生产 OpenAI 客户端验证实际 `/v1/chat/completions` 路径、Bearer 认证头、模型名称和 HTTP 消息格式；服务端是本机模拟兼容模型，不是付费厂商。
- 集成测试覆盖问候不执行工具、模型发起 ping、同轮多个调用、多轮结果完整拼接、未知工具拦截、非法参数、超预算停止与请求无历史隔离。
- 单元与 HTTP 边界测试覆盖模型默认关闭、输入校验、配置脱敏、独立轮数/次数限制、错误工具结果、重复调用 ID、尾随 JSON 参数与客户端关闭。
- 模型请求失败不自动重试，不回传原始供应商错误；工具执行后模型失败，错误响应仍保留已经发生的工具结果。
- 检查可执行 JAR 不包含本地 profile 配置或模板；`phoenix-server/config/application-local.yml` 命中忽略规则。
- `git diff --check` 通过；所有新增方法有简短中文说明，业务 Service 保持接口与实现分离。
- 本轮没有使用真实模型 Key，不以模拟模型证明真实厂商的推理或工具选择能力。没有访问服务器或启动实际故障环境。

## 已知边界

当前聊天需要 MCP 工具服务可用，即使模型最后选择直接回答，前面的工具发现也会访问 MCP。明细不持久化，日志只记请求 ID、代码和数量。各阶段超时不是整个聊天请求的总超时；没有流式输出、历史记忆、鉴权或实际修复权限。
