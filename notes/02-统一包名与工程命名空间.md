# 统一包名与工程命名空间

## 本轮功能

将初始化时的 GitHub 风格命名空间改为简洁的 `com.phoenix`，同步调整源码目录、测试目录和 Maven 坐标。本轮仅调整命名，不改变接口、端口或业务行为。

## 修改的类及作用

| 类 | 新包名 | 作用 |
| --- | --- | --- |
| `PhoenixServerApplication` | `com.phoenix.server` | Agent 控制端启动入口 |
| `PhoenixServerApplicationTests` | `com.phoenix.server` | 控制端启动与 HTTP 健康检查测试 |
| `FrameworkSmokeTests` | `com.phoenix.server` | 模型客户端构建与最小图执行测试 |
| `PhoenixMcpServerApplication` | `com.phoenix.mcp` | 目标机工具服务骨架启动入口 |
| `PhoenixMcpServerApplicationTests` | `com.phoenix.mcp` | 工具服务启动与端点边界测试 |
| `PhoenixDemoApplication` | `com.phoenix.demo` | 最小目标应用启动入口 |
| `PhoenixDemoApplicationTests` | `com.phoenix.demo` | 目标应用健康和探活测试 |
| `DemoController` | `com.phoenix.demo.controller` | 目标应用探活接口 |

没有新增业务类。保留方法实现和中文注释；Java 文件迁移到与新包名一致的目录。

## 其他改动

- 父工程 `groupId` 及三个子模块的父坐标统一改为 `com.phoenix`；`artifactId`、版本和生成的 JAR 名不变。
- 更新 README 中的完整启动类名称、架构说明和 AGENTS 命名约定。
- 已在 IDEA 创建旧启动配置时，需要重新选择新入口类；重新加载 Maven 后模块结构保持不变。
- 无数据库表变更，不修改历史开发记录。

## 验证

- `.\mvnw.cmd -B -ntp clean verify`：清理旧编译产物后完整构建成功，7 项测试全部通过，失败、错误、跳过均为 0。
- 三个应用在新包名下启动测试 HTTP 服务成功，原健康检查与探活行为保持不变，三个可执行 JAR 重新生成。
- 源码和 POM 中无旧命名空间残留，迁移后遗留的空目录已清理，没有删除业务文件。
- `git diff --check`：通过。没有创建远程仓库或推送。
